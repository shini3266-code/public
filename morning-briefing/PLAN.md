# Morning Briefing 구현 계획

> **2026-10-29 변경:** 저장소를 아티팩트 DB에서 Insight Hub 웹앱(Supabase)으로 옮겼다. 화면은 웹앱의 `/briefing`, 예약 작업은 `/api/agent/watchlist`·`/api/agent/briefings`를 쓴다(`task-prompt.md` 참고). 아래 아키텍처·데이터 구조 절은 최초 설계 기록이다.

> 목표: 매일 아침 7시, 경제(매크로·지정학)·산업·관심종목 뉴스를 한국어로 요약한 개인 대시보드를 **추가 비용 없이** 받아본다.
> 작성일: 2026-10-28 · 목표 완료: 2026-10-29

## 1. 확정 사양

| 항목 | 결정 |
|---|---|
| 사용자 | 본인 1명 (비공개 아티팩트) |
| 시장 | 미국 위주 + 한국 + 일본 |
| 언어 | 조사는 영어 원문, 화면은 한국어 |
| 주기 | 매일 1회, 07:00 KST 전 완료 |
| 비용 | 0원 (기존 Claude 구독 사용량 안에서 실행) |
| 화면 순서 | 오늘의 핵심(3줄) → 경제 → 산업 → 종목 카드 |
| 뉴스 형식 | 제목 + 요약 2~3문장 + 🔗 원문 링크 + "의미" 1줄, 특이사항 없으면 "특이사항 없음" |
| 표시 안 함 | 시세, 중요도, 호재/악재 방향 |
| 종목당 뉴스 | 최대 3건 |
| 상장 소식 | 비상장 종목(스페이스X, 앤트로픽)의 상장 관련 뉴스는 오늘의 핵심으로 올림 |
| 종목 편집 | 대시보드에서 직접 추가/삭제, 다음 날 브리핑부터 반영 |
| 알림 | 완료 시 휴대폰 푸시 (핵심 3줄) |
| 보관 | 날짜별 누적 저장, 날짜 이동·종목 필터 |

**경제 범위**
- 매크로: 연준, 물가·고용, 환율(USD/KRW, USD/JPY), 미국 국채금리, 일본 금리(BOJ·JGB), 한국은행
- 지정학: 미중 관계, 관세, 수출통제, 중동, 전쟁 등의 이슈

**산업**: 카드는 1개. 뉴스마다 산업 태그(AI·반도체, 반도체 기판·소재, 전기차·로봇, 우주 등). 태그는 관심종목에서 자동 도출.

**초기 관심종목 (10)**
테슬라(TSLA), 스페이스X(비상장), 앤트로픽(비상장), 엔비디아(NVDA), SK하이닉스(000660), 삼성전자(005930), 삼성전기(009150), 닛토보(3110), 아지노모토(2802), 이비덴(4062)

## 2. 아키텍처

```
┌──────────────────────────┐      매일 06:43 KST
│  Claude 예약 작업          │ ◀── (미국장 마감 06:00 이후)
│  1. 관심종목 목록 읽기       │
│  2. 영어 원문 웹 검색       │
│  3. 선별·한국어 요약        │
│  4. DB에 오늘 브리핑 저장    │──┐
│  5. 푸시 알림 (핵심 3줄)    │  │
└──────────────────────────┘  │ ArtifactData (set)
                              ▼
┌──────────────────────────────────────┐
│  Morning Briefing 아티팩트 (비공개 웹페이지) │
│  · db 저장소                             │
│     briefings/{YYYY-MM-DD}  ← 매일 1건     │
│     config/watchlist        ← 화면에서 편집  │
│  · 페이지는 DB를 실시간으로 읽어 렌더링         │
└──────────────────────────────────────┘
```

- 서버, API 키, 외부 계정이 필요 없다.
- 페이지 코드(디자인)와 데이터(브리핑)가 분리되어 있어서, 디자인을 고쳐 다시 배포해도 쌓인 브리핑은 유지된다.
- 예약 작업은 매번 새 세션으로 시작하므로, 작업 지시문(`task-prompt.md`)이 완결된 문서여야 한다.

## 3. 데이터 구조

### `config/watchlist` (문서 1개)
```json
{
  "items": [
    { "id": "tsla",  "name": "테슬라",   "code": "TSLA",   "market": "US", "listed": true },
    { "id": "spacex","name": "스페이스X", "code": null,     "market": "US", "listed": false },
    { "id": "ibiden","name": "이비덴",   "code": "4062",   "market": "JP", "listed": true }
  ],
  "updatedAt": "2026-10-29T00:00:00+09:00"
}
```

### `briefings/{YYYY-MM-DD}` (하루 1문서)
```json
{
  "date": "2026-10-29",
  "dow": "목",
  "generatedAt": "2026-10-29T06:58:12+09:00",
  "core": ["핵심 1", "핵심 2", "핵심 3"],
  "econ": [
    { "tags": ["매크로", "연준"], "title": "...", "summary": "...", "meaning": "...", "url": "https://..." }
  ],
  "industry": [
    { "tags": ["반도체 기판·소재"], "title": "...", "summary": "...", "meaning": "...", "url": "https://...",
      "related": ["ibiden", "semco"] }
  ],
  "stocks": {
    "tsla": [ { "title": "...", "summary": "...", "meaning": "...", "url": "https://..." } ],
    "sec": []
  }
}
```

- `related`: 산업 뉴스를 종목 필터에 연결하는 키
- `stocks.{id}`가 빈 배열이면 화면에 "특이사항 없음"
- 용량: 하루 약 10~30KB, 1년 약 5~10MB → 문제 없음. 1년 경과분 정리 규칙은 필요해지면 추가.

## 4. 페이지 변경 사항 (목업 → 실제)

1. `capabilities: { db: {}, user: {} }` 선언
2. 하드코딩된 예시 데이터 제거
3. 로드 시 `claude.use("db")`
   - `briefings`를 날짜 내림차순으로 구독 → 날짜 이동 버튼에 연결
   - `config/watchlist` 구독 → 필터 칩, 종목 카드 순서
4. 종목 편집 → `config/watchlist` 문서 업데이트
5. 상태별 화면
   - DB 연결 전: 로딩 표시
   - 브리핑 0건: "첫 브리핑은 내일 아침 7시에 도착합니다"
   - 오늘 브리핑 없음(작업 실패 등): 가장 최근 날짜를 보여주고 상단에 "오늘 브리핑이 아직 없습니다" 표시
6. 원문 링크 🔗는 `url`이 있을 때만 표시

## 5. 예약 작업

| 설정 | 값 |
|---|---|
| 이름 | Morning Briefing |
| 일정 | `CRON_TZ=Asia/Seoul 43 6 * * *` (매일 06:43 시작 → 7시 전후 완료) |
| 알림 | 푸시 ON, 이메일 OFF |
| 지시문 | `task-prompt.md` 전문 |

- 06:43은 서버 혼잡을 피하기 위해 정각에서 조금 앞당긴 시각이다. 미국 서머타임 종료(11/1) 이후 미국장은 06:00 KST에 마감하므로 마감 결과가 반영된다.
- 승인 설정은 서버가 정한다. 실행 중 승인을 요구하면 작업 설정에서 "Automatically approve"로 바꿔야 무인 실행이 된다.

## 6. 작업 순서 (내일까지)

| # | 작업 | 담당 | 완료 기준 |
|---|---|---|---|
| 1 | 디자인 확정 | 사용자 | 목업 OK |
| 2 | 페이지에 DB 연결, 예시 데이터 제거, 빈 상태 화면 | Claude | 빈 대시보드가 정상 표시 |
| 3 | `config/watchlist`에 초기 10종목 저장 | Claude | 칩 10개 표시 |
| 4 | 지시문으로 **수동 1회 실행** → 오늘자 브리핑 저장 | Claude | 실제 브리핑이 화면에 표시 |
| 5 | 결과 검토 (요약 품질, 길이, 링크, 태그) → 지시문 조정 | 사용자 + Claude | 사용자 OK |
| 6 | 예약 작업 생성 | Claude | 작업 목록에 등록 |
| 7 | 다음 날 아침 자동 실행 확인 | 사용자 | 07시 전후 푸시 수신 |

## 7. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 유료 기사(WSJ, FT, 닛케이 등)는 본문을 읽기 어려움 | 로이터, AP, CNBC, 회사 IR·보도자료, 공시 등 접근 가능한 출처를 우선한다 |
| 오래된 기사가 섞임 | 지시문에 "최근 24시간(월요일은 주말 포함 72시간)"을 명시하고, 날짜가 확인되지 않는 기사는 제외한다 |
| 확인되지 않은 루머 | 요약에 "~라는 보도" 형태로 출처 성격을 드러낸다 |
| 앤트로픽 뉴스 편향 우려 | 다른 종목과 동일한 기준으로 요약하고, 부정적 뉴스도 그대로 싣는다 |
| 작업 실패나 지연 | 화면에 최신 날짜와 "오늘 브리핑 없음"을 표시한다. 필요하면 수동으로 재실행한다 |
| 실행 시간과 사용량 | 검색 15~25회 수준. 구독 사용량 한도에 닿으면 종목당 검색 수를 줄인다 |
